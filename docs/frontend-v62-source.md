- 桌面与窄屏的布局、导航、五标签、设备树及机箱采用原型尺寸和 Tabler SVG 图标。图标路径保存在 `icons.ts`，MIT 许可文本保存在 `LICENSES/texts/tabler-icons-MIT.txt`，没有新增运行时框架或 npm 依赖。
- 右侧详情按需打开，提供真实指纹、连接、独立终端及白名单查询入口；处理过程与能力说明保持折叠。底部设备详情显示当前设备真实元数据。
- 工具区始终常驻；展开/还原仅调整真实终端区域，不复制 SSH 会话。执行记录按当前设备过滤；切换标签保留现有终端字节流。
- 拓扑分层居中排列，采用原型 140×66 节点、层级背景和邻接高亮；未知邻居可在图内选中查看关系，不冒充已登记设备，也不触发设备操作。没有复制流量或链路追踪演示动画。

## 后端依赖与来源

保留了 `~/yigou`（原始开发工作区） 原有未提交的 `App.vue` 审批/自主授权界面及相关样式，这是本次 UI 必需的安全交互。其余原有 Rust、测试和文档改动没有纳入提交，原工作区文件未修改。

**此分支不是与远端旧 Rust 核心完全兼容的整包发行。** AI 查询、计划及自主执行必须配合本机尚未发布的后端安全变更：

- `system_status.ai_mode = optional_autonomous`，作为启用 AI 界面的能力前提。旧核心不会收到前端 AI 请求；不能退回旧的模型直接配置路径。
- `ai_plan` 返回绑定设备、请求哈希、过期时间和结构化配置的可审批计划。
- `config_execute_approved(deviceId, planId, reviewedHash, approval)` 在 Rust 内校验审批、设备会话、计划时效、备份、命令范围与回读。
- `ai_autonomous(deviceId, prompt, requestId, consent)` 保留逐请求授权与后端高风险拦截。

对应未发布 Rust 文件位于原工作区 `app/src-tauri/src/{ai/mod.rs,commands/mod.rs,devices/configure.rs,tasks/mod.rs,main.rs}`。前端不实现或替代这些安全检查。普通设备查询、SSH 指纹登记、终端、备份历史与校验继续使用现有 IPC。能力标识只是界面门禁，后端必须独立强制校验每次执行。

## 源码复核与修正

本次复核仅阅读 Vue/TypeScript/CSS、原型源文件及原工作区 Rust/worker 的字段与执行顺序；没有执行编译、类型检查、测试、设备请求或应用渲染。再次通过公网读取的 `device-dock.css` 与 `topology.js` 仍与本机参考字节一致。

发现并在源码中修正：

- 窄屏拓扑原来的通用 `>span`、后代 `i` 选择器会把文本布局和选中标记样式套到机箱端口阵列。改为专用文字与状态标记类；无名邻居没有 chassis/name 时使用独立观察编号，避免合并为同一节点。
- 旧的段落字号 `!important` 会覆盖新版首页字号；移除该优先级。折叠侧栏的设备按钮内边距会挤压 45px 机箱，工具区终端的旧 80px 最小高度也会超过低屏剩余空间，均已定向调整。
- 配置流程原来用 `save_status=verified` 判断回读，导致不请求保存但已完成回读的任务被错误标为失败；并把“尝试写入”显示为命令全部完成。现分别读取 Rust/worker 的命令确认计数、实际 config checks、执行结果和备份字段，证据不足明确显示“未核验”。配置前备份必须跨过后端验证关口才显示完成。
- 会话变化时将尚未提交的本机计划标为失效；过期响应不再挂入当前会话的计划/邻接视图。AI 处理中状态按请求所属设备显示。
- 断开、重新登记指纹及组件卸载后，仍在打开的终端返回时会请求关闭，不再加入界面。该处理不替代 Rust 的 SSH 指纹验证与独立会话管理。
- 切换设备时，若备份/差异标签正打开，会读取新设备历史；设备清单、任务和同设备备份历史采用最新请求结果，避免较旧响应覆盖新状态。
- 不支持 neighbors 查询的平台禁用拓扑发现入口，并在调用入口按现有厂商白名单拦截；仍由 Rust/worker 独立校验实际操作权限。

上述为源码修正记录，不是运行验证通过的证明。旧远端 Rust 核心仍不提供新版审批/自主执行接口，AI 界面继续按能力标识禁用；未完成真实设备联调及像素级 1:1 渲染验收。
