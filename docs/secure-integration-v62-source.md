## 静态审阅结论

- `ai_chat` 只给模型白名单查询工具；`ai_plan` 只生成结构化计划。模型不获得写入或终端工具。
- 计划绑定设备、会话摘要、主机信任文件摘要、命令/保存/回读条件的 SHA256 和 15 分钟有效期；模型请求起始会话也绑定到计划生成。发送前再次核对会话、主机信任记录和有效期。
- 人工执行接口要求完整 approval 和确认短语，加载原计划内容，检查哈希后原子消耗计划并创建执行记录；消费和记录同一事务，重复请求只返回历史证据。
- 自主执行要求本轮 `consent:true`，持久化请求 UUID 防重放，要求本轮配置查询成功，仅执行本请求产生的最多 12 行低风险计划。物理接口描述及 VLAN 创建/命名以确定性语法约束；逻辑接口及危险变更转人工审阅。自主执行错误保留已有持久记录及未知态，不推断未写入。
- Rust 在发送前生成加密备份并重新解密校验密文、元数据、长度和摘要。Python 顺序下发、首错停止，按真实配置/启动配置回读核验；Rust 检查命令确认数量、回读及保存状态，保存后置备份。失败、部分结果和断线不报告成功，不自动重试或回滚。未知态不继续尝试设备清理命令。
- Rust 与 Python 拒绝模式控制、保存、重启、擦除、组合命令及其首词缩写。Python 回读条件覆盖所有已识别写入值；未知修改语法不能借另一条命令的核验获得成功。
- 静态对照 `optional_autonomous`、三类 AI 命令、`config_execute_approved` 的 camelCase 参数及 snake_case approval、`backup_verify`、`task_status`、`yigou:event`、`config.checks`。注册及返回字段与最新前端一致。Python RPC 仍为协议 1，无需新增授权 RPC；本次补充 worker 的命令与证据防线。

## 本轮根因修复（源码静态检查，未运行）

- **配置基线**：模型在本轮先查询运行配置，未成功读取、超过 48 KiB 或输出被截断时不得形成可审批计划。Rust 在生成计划时对用户可见的脱敏查询作一致性比对，并通过现有经过结束标记验证的配置备份读取通道，只计算**完整原文 SHA256**（不保存原文到计划或事件）。审批前、加密备份后、真正发送前比对完整摘要；敏感配置行变化也会使旧计划失效。旧计划缺少摘要时拒绝执行。
- **目标位置核验**：Python 不再仅凭全文包含某个新值报告成功；需在指定接口/VLAN 配置段落或全局 sysname/hostname 位置找到各项可识别写入，保存启动配置时还必须在对应段落再确认。不支持的语法和无法解析的设备输出只报告 `applied_unverified`（已尝试但未核验），不会冒充成功。
- **本机并发**：主机密钥登记、连接、断开、自动配置与终端新建受同一把配置锁串行保护；人工终端输入遇到锁占用立即返回 `CONFIG_BUSY`，不排队后补发送；前端丢弃待发送字节并保留原 SSH 会话，终端读取仍可继续。外部管理员的独立连接不受本机锁控制，因此仍采用执行前配置摘要重检。
- **验收输入更新**：新版 Windows 模型模拟服务只调用 `device_query`（运行配置）和 `device_propose_plan`，待 Rust 完成人工审批后才通过 `config_execute_approved` 执行；跨轮历史工具调用不再冒充本轮证据。补充配置基线变化、错误接口描述与终端锁占用的测试源码，但**全部未运行**。

**限制**：厂商配置输出形式并非统一的语法树；段落核验为保守解析，无法可靠识别时拒绝宣布成功。配置摘要读取和真正发送之间仍可能受到本机外部独立 SSH 会话影响，不能宣称跨系统绝对原子性。大配置或不稳定配置快照可能要求重新查询或改为人工操作。需要真实型号、并发、故障注入和 Windows 本机验证，才能认定安全行为有效。
